------------------------------------------------------------------
Бонусные задачи.
Язык: C.
Срок: до конца лекции.
------------------------------------------------------------------

Нужно измерить производительность нескольких операций, типичных
для повседневного программирования, чтобы понять их стоимость.

Можно выбрать одну задачу, выполнить её и сразу представить на
лекции код и результаты. Если останется время, выбрать следующую.
Если участников больше, чем задач, некоторые задачи могут
повторяться.

Каждый тест производительности многократно вызывает одну или
несколько функций: тысячи или миллионы раз. До и после цикла нужно
сохранить метку времени и вычислить длительность. Чтобы уменьшить
шум, запускайте тест несколько раз и приводите минимальную,
максимальную и медианную длительности.

Параметры теста можно задавать аргументами командной строки или
константными глобальными переменными.

Для измерения времени используйте `clock_gettime(CLOCK_MONOTONIC)`.

Пример кода:
```
    array times;
    for (int run_i = 0; i < 5; ++i) {
        uint64_t start_ts = clock_gettime(CLOCK_MONOTONIC);
        for (uint64_t i = 0; i < iteration_count; ++i) {
            <тестируемая операция>
        }
        uint64_t duration = clock_gettime(CLOCK_MONOTONIC) - start_ts;
        double time_per_operation = duration / iteration_count;
        times.append(time_per_operation);
    }
    print("min: ", times.min());
    print("med: ", times.median());
    print("max: ", times.max());
```

Пример результата каждого теста:
```
<Сценарий 1>
    min: ...
    max: ...
    med: ...
<Сценарий 2>
    min: ...
    max: ...
    med: ...
<...>
```

Для каждой задачи приложите текстовый файл с результатами со своей
машины.

## (1) Измерение часов

Баллы: 3.

Измерьте `clock_gettime()` с `CLOCK_REALTIME`, `CLOCK_MONOTONIC` и
`CLOCK_MONOTONIC_RAW`. Вызовите функцию с каждым параметром 50 млн
раз и определите время одного вызова.

## (2) Пропускная способность сокетов

Баллы: 6.

Измерьте пропускную способность пары UNIX- и TCP-сокетов. Создайте
сервер через `socket() + bind() + listen()`, подключите клиента через
`connect()`, затем примите его через `accept()`. Получится пара
сокетов; переведите её в неблокирующий режим.

В двух отдельных процессах или двух потоках клиент должен посылать
большой объём данных пакетами, а сервер — принять всё. Например,
клиент отправляет 15 ГБ пакетами по 16 КБ в каждом `send()`, а сервер
вызывает `recv()` с буфером 16 КБ. Общий размер и размер пакета должны
настраиваться. Измерьте время передачи общего объёма как минимум для:

* 15 ГБ пакетами по 16 КБ;
* 15 ГБ пакетами по 1 КБ;
* 15 ГБ пакетами по 48 КБ;
* 15 ГБ пакетами по 512 Б.

`send()` может передать меньше данных, чем ему передали. Целевая
метрика — скорость в МБ/с.

## (3) Захват мьютекса pthread

Баллы: 4.

Измерьте `pthread_mutex_lock/unlock` в N потоках. Запустите N потоков
(число настраивается), каждый непрерывно захватывает и освобождает
мьютекс. При каждом захвате увеличивайте глобальный счётчик. Определите
время заданного общего количества захватов/освобождений в зависимости
от числа потоков, в расчёте на одну пару lock/unlock. Общее количество
относится ко всем потокам вместе, а не к каждому отдельно.

Проверьте как минимум:

* 10 млн захватов в 1 потоке;
* 10 млн захватов в 2 потоках;
* 10 млн захватов в 3 потоках.

## (4) Создание и join pthread

Баллы: 2.

Многократно создавайте и присоединяйте пустой поток. Измерьте
приблизительную стоимость одной пары create+join, выполнив цикл
100 тыс. раз.

## (5) Атомарные операции

Баллы: 3.

Измерьте атомарную запись и инкремент в N потоках. Запустите N
потоков, каждый атомарно записывает в значение V и увеличивает
глобальный счётчик C, пока тот не достигнет заданного предела.
Определите скорость записи в зависимости от числа потоков и порядка
памяти. Целевая метрика — время на 1000 итераций.

Тело рабочего потока должно быть примерно таким:
```
void *worker_f(void *arg)
{
    volatile uint64_t random_on_stack;
    while (__atomic_add_fetch(&global_counter, 1,
        __ATOMIC_RELAXED) < TARGET)
    {
        __atomic_store_n(&value, random_on_stack, BENCH_MEM_ORDER);
    }
}
```

Случайное `volatile`-значение в стеке не даёт оптимизатору удалить
цикл. В тесте важна именно запись, а не только инкремент: иначе на
x86 разница между порядками памяти не проявится. Инкремент всегда
должен быть relaxed; настраивается только порядок записи.

Проверьте как минимум:

* 100 млн инкрементов в 1 потоке с relaxed-порядком;
* 100 млн инкрементов в 1 потоке с последовательно согласованным
  порядком;
* 100 млн инкрементов в 3 потоках с relaxed-порядком;
* 100 млн инкрементов в 3 потоках с последовательно согласованным
  порядком.

## (6) Сигнализация pthread cond

Баллы: 4.

Измерьте стоимость `signal` и `broadcast` в зависимости от числа
потоков. Запустите один поток, выполняющий сигнализацию, и N потоков,
выполняющих `pthread_cond_wait()`. Условная переменная должна быть
защищена мьютексом. Измерьте время заданного числа вызовов
сигнализации: поток должен вызывать `pthread_cond_signal()` либо
`pthread_cond_broadcast()` в зависимости от параметров теста.

На каждой итерации захватывайте мьютекс, выполняйте сигнализацию и
освобождайте мьютекс. Удерживать его весь цикл нельзя: ожидающие
потоки тогда не смогут проснуться.

Целевая метрика — время одного вызова сигнализации.

Проверьте как минимум:

* 1 млн вызовов `signal()` при 1 ожидающем потоке;
* 1 млн вызовов `broadcast()` при 1 ожидающем потоке;
* 1 млн вызовов `signal()` при 3 ожидающих потоках;
* 1 млн вызовов `broadcast()` при 3 ожидающих потоках.

## (7) Ложное совместное использование

Баллы: 4.

Проверьте, насколько сильно потоки влияют друг на друга, даже если
не обращаются к одним и тем же данным. Создайте массив чисел
`uint64_t`, затем запустите N потоков. Каждый поток в цикле
увеличивает своё число в массиве.

Не дайте компилятору свернуть цикл в одну операцию `+=`. Например,
можно сделать переменную-счётчик цикла `volatile`; тогда компилятор,
вероятнее всего, не встроит и не удалит цикл.

Если потоки находятся в массиве, поток с индексом A должен работать
с `arr[A]`. Измерьте время, за которое все потоки доведут свои числа
до заданного значения.

Затем разнесите числа: поток с индексом A использует `arr[A * 8]`.
Расстояние между числами должно быть не меньше 64 байт. Повторите
измерение.

Целевая метрика — время на 1000 инкрементов. Каждый поток должен
довести своё число до заданного значения; это не общее число
инкрементов.

Проверьте как минимум:

* 100 млн инкрементов в 1 потоке;
* 100 млн инкрементов в 2 потоках с близко расположенными числами;
* 100 млн инкрементов в 2 потоках с разнесёнными числами;
* 100 млн инкрементов в 3 потоках с близко расположенными числами;
* 100 млн инкрементов в 3 потоках с разнесёнными числами.
